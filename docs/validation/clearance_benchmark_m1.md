# Clearance-run compute benchmark, Milestone 1

Generated by `python experiments/benchmark_clearance.py`. All numbers are in `clearance_benchmark_m1.json`.

A clearance run continues from the end of a 5 minute horizon under the baseline controller with no new demand, until the network and the insertion backlog are empty. It supplies the second term of Step Zero's cost J = horizon vehicle-time + clearance vehicle-time, with a censoring penalty for vehicles still present at the cap (provisional: 60 minute cap, 60 vehicle-minutes per vehicle). Each clearance here was run with a 90 minute limit so that 30, 60 and 90 minute caps can be compared from the same run.

The stress case holds I1 eastbound red for the 20 minutes before the checkpoint (a test-only override), so a large queue and insertion backlog must clear.

## Compute

One clearance branch took 1.9 to 9.4 s of wall time on one core (x86_64, Python 3.13.16), of which starting a fresh process and resuming the checkpoint is the first figure in the table. The simulation steps at 0.1 s with the baseline controllers, detectors and ledger running.

Clearance is therefore cheap: under the baseline controller it costs a few seconds per branch, so a paired counterfactual evaluation (a baseline branch and a candidate branch per decision, each a 5 minute horizon plus a clearance) costs well under a minute on one core, and branches run in parallel as independent processes. The cost grows with the backlog to clear (the stress case is the slowest).

All clearances finished with zero collisions and zero ledger identity violations: True.
